# 業務自動化ツアー

`/business` は困りごと → 体験 → 費用 → 導入・相談の4ステップです。広い画面は1画面に収め、小さい画面は必要な範囲で縦にスクロールします。

## 編集箇所

- `src/components/business/tour/BusinessTour.tsx`: 入口、解決策パネル、料金、相談、フォーム。
- `Demos.tsx`: 集計、請求書、問い合わせの体験。
- `data.ts`: 困りごとの文章・人物位置・サンプル明細・顧客マスタ。
- `config.ts`: Formspreeの公開フォームID。
- `tour.module.css`: レスポンシブ・アニメーション。色は `src/styles/tokens.css`。
- `public/business/ASSETS.md`: 画像の原本・変換方法。原寸PNGはチャットで別途提供。

## デモの動作

集計は3種類の明細と顧客マスタを見て、表記ゆれを正規化し、重複・未登録の扱いを選択して集計します。結果とCSVは同じ計算結果から生成します。重複除外・未登録を含む場合は422,000円です。戻っても各デモの操作状態を保持します（再読み込みで初期化）。

請求書は見本明細から税率10%で計算し、日本語の見本PDFを保存します。問い合わせはフォームの種別によるルールベースの振り分けと返信案の編集です。AI APIや実メール送信はありません。実ファイルのアップロードは行いません。

## 問い合わせの接続（公開前に必要）

現状は受信先未確定のため `formId` が空で、準備中表示・送信ボタン無効です。送信成功の偽装はありません。

1. 所有者のFormspreeアカウントでフォームを作り、受信先Gmail等を確認します。
2. 発行された公開フォームIDだけを `src/components/business/tour/config.ts` の `formId` に設定します。APIキーやGmailパスワードは不要・記載禁止です。
3. 再ビルド後、テスト送信の許可を得て、サイト内の完了表示と受信先の到着を確認します。迷惑メール、送信上限、スパム対策、利用可能なドメイン制限も管理画面で確認してください。
4. HTTPエラー・通信タイムアウト時には成功扱いせず入力を保持します。失敗時の表示と再送も公開前に確認します。

送信項目: 業務、相談/質問の種別、会社名（任意）、氏名、メール、本文。必須入力・メール形式・プライバシーポリシー確認、二重送信防止、15秒のタイムアウト、honeypotあり。フォーム送信はFormspreeへの直接POSTです。実受信の確認は今回の対象外です。

## 検証

`npm run typecheck` / `npm run lint` / `npm run build:export`。
`e2e/demo.spec.ts` は集計ロジックと新しいUI導線をカバーします。UIテストは通常のCI環境で `npm run test:e2e` を実行できます。今回のUI検証はクラウドブラウザで実施、ロジックのテストは単独実行済みです。

フォントは同じファミリーをFontsourceで同梱し、ビルド中のGoogle Fonts通信を不要にしました。dev出力は `.next-dev`、buildは `.next` と分離し、プレビューと静的ビルドの競合を避けています。
